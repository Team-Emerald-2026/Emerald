# 京都TECH学園祭 来場者向けアプリ（フロントエンド）

学園祭来場者向け・店舗向けのモバイルWeb UIです。来場者はブース、呼び出し番号、イベント、お知らせ、校内マップを確認し、店舗側は受付番号、待ち時間、会計、売上を管理します。

- 元デザイン（Figma）: https://www.figma.com/design/j3VT8gNDqnpmMIILQFN8z8/Tokyo-Disney-Resort-App

---

## 画面別：実装されている機能

### 1. ホーム（`/`）— `src/app/components/Home.tsx`

- **ヒーローカード（1枚）**
  - タイトル: 「京都TECH学園祭」
  - 背景動画: `/hero.mp4`
  - グラデーションオーバーレイ（青〜紫）
  - カード全体クリックで **`/attractions`** へ遷移
- **待ち人数が少ないブース**: バックエンド API から店舗・マップ情報を取得し、待ち人数が少ない順におすすめ表示（「待ち3人」「待ちなし」など。文字表示モードの店舗は設定した文字を優先）
- **クイックメニュー（3件）**
  - 本日の待ち状況 → `/attractions`
  - モバイルオーダー → `/restaurants`（今後呼び出し番号またはカミングスーンに変更予定）
  - マップ → `/map`
  - 各項目: アイコン色付きブロック、タイトル、説明文、右矢印

### 2. ブース待ち状況（`/attractions`）— `src/app/components/Attractions.tsx`

- ページタイトル: **「ブース待ち状況」**
- **カテゴリフィルタ（チップ）**: すべて / 体験 / フード（ステージ・イベントものは「すべて」でのみ表示）
- **一覧カード**
  - バックエンド API の店舗情報とマップ情報から、ブース名、場所、待ち人数を表示
  - 表示の決め方は `src/app/lib/waitDisplay.ts` に集約（待ち0人は「待ちなし」、閉店中は「準備中」、文字表示モードは設定した文字を優先）
  - 色分け: 4人以下は緑、5〜7人は黄、8人以上は赤
  - 「人気」は待ち人数が8人以上のブース（暫定。正式定義は今後決定）
  - 「詳細を見る」ボタン（またはカード上部）で、同一画面内に詳細を展開（URL は `?detail=店舗ID`）
  - 詳細には、ブースの説明、メニューと値段（販売中のもの）、場所、待ち状況を表示。開いたときだけ `GET /v1/restaurants/{id}` で取得し、一度取得したものは使い回す
  - 説明やメニューが未登録のときは、その旨を表示（体験ブースなどでメニューがない場合は、メニューの欄を出さない）
  - マップボタンで `/map?store=<store_id>` へ遷移
  - フードブースのみ現状の注文導線を表示
- **フッター注意書き**（青系ボックス）: 待ち人数はページを開いた時点の目安である旨（自動更新はしない）

今後の変更:
- 注文対象外表示を削除する
- ブース詳細に、電子呼び出し番号を加える（説明、メニュー、場所、待ち状況は実装済み）
- 待ち人数が少ないブースをクリックすると詳細が自動で開き、画面中央に表示されるようにする

### 3. 注文・呼び出し番号（`/restaurants` 配下）— `src/app/components/Restaurants.tsx`

共通ヘッダー:

- タイトル: 現状 **「モバイルオーダー」**
- サブナビ（`Link`）: **選ぶ** / **確認** / **番号**
- 今後、モバイルオーダーと予約システムはなくし、カミングスーンまたは呼び出し番号確認画面に変更する

#### 3-1. 現状の注文画面（`/restaurants`）

- 説明用の青系情報ボックス（注文の案内）
- **店舗カード**
  - バックエンド API の店舗情報を表示
  - 商品が未登録の店舗は準備中として表示
- **メニュー行**
  - 現状、来場者向けメニュー API との接続は限定的
  - 今後は注文機能を削除またはカミングスーンにするため、ブース詳細のメニュー一覧表示へ役割を移す
- **カートサマリー（固定バー）**（注文画面のみ、カートに1点以上あるとき）
  - 点数合計、金額合計
  - **「カートの中を確認」** → `/restaurants/cart` へ遷移
- ページ下部: モバイルオーダー説明（青系ボックス）

カート状態は `useState` のオブジェクト `{ [商品ID]: 数量 }` で保持。ページ遷移しても同一コンポーネント内のため状態は維持されます。

#### 3-2. カート確認（`/restaurants/cart`）

- 見出し: **「カートの中を確認」**
- カート空のとき: メッセージと **「注文画面に戻る」**（`/restaurants`）
- カートに商品があるとき:
  - 行ごとに商品名、店舗名、**数量の増減（+/-）**、行小計
  - **「削除」**（枠付きボタン）で当該商品をカートから削除
  - **合計**金額
  - **「戻る」**（注文画面）、**「注文を決定」**（`/restaurants/status`）

#### 3-3. 注文番号（`/restaurants/status`）

- **モバイルオーダー番号**を表示（会計確定時に店舗側で発行された最新番号）
- 受け取り案内の説明文

### 4. 校内マップ（`/map`）— `src/app/components/Map.tsx`

- バックエンド API の `map/facilities` から施設・ブース情報を取得する
- 1F〜8F の校内マップ画像を表示し、その上にブースピンを重ねる
- `store` または `facility` クエリで対象施設を選択できる
- 選択中のブースからブース詳細へ遷移できる

UI:

- 現状は階層・ブースタイプのフィルタトグルがある
- 今後、マップのフィルタは削除する
- 校内マップ画像に、施設ピンと選択中ブースの詳細カードを表示する
- 場所・ブースの種類は 体験（`booth`）/ フード（`food`）/ 案内（`information`）/ 金券販売（`shop`）/ 運営サポート（`support`、運営サポート本部用）/ 男子トイレ（`toilet_men`）/ 女子トイレ（`toilet_women`）/ 男女トイレ（`toilet`、男女が同じ場所にあるトイレ）の8つ。マップ編集ではこの8つを選べる（管理画面の店舗の種類は トイレ3種 を除く5つ、店舗画面の種類は さらに 運営サポート を除く4つ）。以前の 救護室・イベントもの は、登録済みの場所の表示のためだけに残している
- 階の名前（「3F の地図」）は地図の上に重ねず、地図の枠の外（すぐ上）に表示する
- ピンは部屋番号の文字ではなく、種類ごとのアイコン（色付きの丸）で表示する。選択したピンの上に、ブース名（と部屋番号）の吹き出しを出す
- 地図の下に、アイコンの意味（凡例）を表示する。部屋番号は一覧とカードに残る
- ページ下部: 緑系情報ボックス（校内マップの案内）

### 5. 404（`*`）— `src/app/components/NotFound.tsx`

- メッセージ: ページが見つかりません
- **ホームに戻る**（`/`）、**マップを見る**（`/map`）

### 6. 店舗向け画面（`/store/*`）— `src/app/components/store/`

- **ログイン**（`/store/login`）
  - ログインID・パスワードでバックエンド認証し、店舗セッションを保持
  - 今後「初めての方は 新規登録」を削除し、`/admin` への導線を追加する
- **店舗登録**（`/store/register`）
  - 現状は店舗名、説明、ログインID、パスワードで新規登録できる
  - 今後、管理画面側の店舗作成へ移す予定
- **レジ**（`/store`）
  - 店舗情報で登録したメニューから商品を選び、会計すると、サーバー（`POST /v1/booth/accounting/orders`、`settle: true`）に注文を登録して精算する
  - 受付番号（C-101, Y-101... のようなブース別 prefix）はサーバーが発行。登録に成功してから表示する
  - 連打しても二重に送らない。失敗したときはカートを残してやり直せる。通信が途中で切れたときは、登録済みかもしれない旨を表示する
  - 会計すると、サーバー側で待ち人数が +1 される
- **待ち人数管理**（`/store/waiting`）
  - サーバーの待ち人数を5秒ごとに取得して表示（レジの会計・提供済みに追随）
  - 数え違いの補正用に `+1 / -1`（`current_queue_delta`。サーバーが最新の値に足し引きする）。直前の補正は「元に戻す」で取り消せる
  - 連打した分は画面の中で数えておき、最後に押してから1秒後に増減の合計を1回だけ送る（送信中に押した分は次にまとめる。画面を離れるときは待たずに送る）。送れなかったときは押した分を取り消して最新の人数に戻す
- **受付番号表示**（`/store/ticket`）
  - サーバーの注文のうち、提供待ち・呼び出し中のものを5秒ごとに取得して表示
  - 各行で「呼び出し」→「提供完了」を操作（それぞれサーバーに送ってから反映）。他の端末で状態が変わっていた場合は、最新の状態に更新する
  - 各行の「注文キャンセル」で、提供待ち・呼び出し中の注文をキャンセルできる（確認あり。待ち人数が1人減り、売上から外れる。元には戻せない。返金はアプリの外で行う）
  - 「大きく表示」は見た目専用（この端末だけ）で、呼び出し状態とは独立
  - 提供待ちが0件のときは大きく表示番号を `---`（なし）表示
- **ダッシュボード**（`/store/dashboard`）
  - バックエンド API から店舗名、説明、待ち人数、総売上、営業状態を取得（5秒ごとに更新）
  - 提供待ち一覧はサーバーの注文を表示
- **提供済み履歴**（`/store/served`）
  - サーバーの提供済みの注文を、新しい順に確認（直近1時間・本日の絞り込み、検索）
  - 「未提供に戻す」で提供待ちに戻せる（サーバー側で待ち人数も +1 される）
- **店舗情報**（`/store/profile`）
  - 店舗名、説明、ブース種別、営業状態、メニュー（商品名・値段）を閲覧・編集する

### 7. 今後追加する画面

- `/events`: イベント・お知らせ一覧
- `/admin`: 管理画面。新規店舗作成、総収益、店舗情報の閲覧・編集・削除、分析・可視化
- `/monitor`: 校内モニター向け呼び出し番号一覧

## 現在の制約・今後の拡張

- 店舗ログイン、ログアウト、ダッシュボード、レジ（会計と精算）、呼び出し、提供済み、待ち人数は、すべてバックエンド API（`/api/v1/booth/*`）に接続済みです。注文・待ち人数・売上はサーバーが正で、複数の端末から同じ内容が見えます。
- `localStorage`（キー `kt_festival_state_v1`）に残すのは、店舗／管理者のログイン情報と、呼び出し画面で「大きく表示」している番号（この端末の表示だけ）です。以前保存していた注文・待ち人数は、起動時に自動で消えます。
- 画面の更新は、5秒ごとの取得（ポーリング）で行います。来場者向けのブース一覧は、ページを開いたときに1回だけ取得します。
- 待ち時間は分ではなく「待ち人数」で表示します。`current_wait_min`（1人当たりの分数）と、API の `estimated_wait_min` は、いまの画面では使っていません。
- 注文の登録には重複防止の仕組みがありません。通信が途中で切れたときは、画面の案内に従って、登録済みかどうかを確認してからやり直します。
- モバイルオーダーと予約システムは今後なくし、カミングスーンまたは呼び出し番号確認へ置き換えます。
- 複数端末でのリアルタイム同期（WebSocket 等）や本番運用向け監査機能は今後の拡張対象です。
